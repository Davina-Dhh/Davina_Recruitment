# Davina 秋招工作台 · 产品需求文档（PRD）

> 版本：v1.3｜产品：Davina 秋招工作台｜形态：Web 工作台 + Agent 流水线 + Agnes LLM 点评  
> 部署：支持本机调试与服务器公网访问｜数据层：Hiring-Radar｜产品层：Streamlit｜大模型：Agnes 2.5 Flash

---

## 1. 背景与问题

秋招岗位信息分散在飞书招聘、Moka、北森及各公司官网。求职者（尤其江浙沪、多赛道）面临：

| 痛点 | 表现 |
| --- | --- |
| 信息分散 | 需在多个 ATS / 官网间反复切换 |
| 筛选成本高 | 关键词、地点、时效难以统一过滤 |
| 链接易失效 | ATS 中转链、错误详情页影响投递 |
| 难沉淀 | 感兴趣岗位缺少本地清单与状态跟踪 |
| 流程黑盒 | 「Agent」若只是结果页，无法解释每一步做了什么 |

传统做法是手动打开官网检索，难以规模化，也不利于作为「AI 产品」案例讲清能力边界。

---

## 2. 产品目标

### 2.1 一句话定位

**Davina 秋招工作台**：面向校园招聘的多源岗位情报工作台——自动拉岗、规则过滤、流程可视、AI 匹配点评、本地感兴趣清单。

### 2.2 目标用户

- 主用户：秋招 / 实习求职者（产品、AI、职能等方向）
- 次用户：需要演示 Agent / 工具型产品能力的 AI 产品经理候选人（作品集场景）

### 2.3 成功标准（能力向）

1. 支持飞书 / Moka / 北森等多源自动拉岗，公司池可扩展  
2. 单公司精查与赛道批量扫可用；江浙沪 / 关键词 / 近 N 天可配置  
3. Agent 流水线可回放（采集 → 过滤漏斗 → 命中）  
4. 接入 Agnes 后，可对岗位做匹配打分与投递建议  
5. 感兴趣清单可本地保存、改状态、导出  

---

## 3. 用户故事

1. **作为**求职者，**我希望**选一家公司一键拉岗，**以便**快速浏览 JD 与链接。  
2. **作为**求职者，**我希望**按赛道扫多家公司并按江浙沪过滤，**以便**缩小投递范围。  
3. **作为**求职者，**我希望**把岗位加入感兴趣清单并标记「准备投递/已投递」，**以便**跟进进度。  
4. **作为**求职者，**我希望**对未入库公司先搜官网、再粘贴门户链接接入，**以便**后续也能自动拉岗。  
5. **作为**求职者，**我希望**AI 结合我的画像点评岗位，**以便**决定优先投哪些。  
6. **作为**求职者，**我希望**上传简历并对照 JD 得到匹配度与改简历建议，**以便**针对性优化材料。  
7. **作为**产品演示者，**我希望**看到 Agent 每一步在做什么，**以便**讲清系统如何工作。

## 4. 功能范围

### 4.1 核心功能

| 模块 | 说明 | 优先级 |
| --- | --- | --- |
| 单公司精查 | 选公司 + 关键词检索 | P0 |
| 赛道批量扫 | 按画像赛道扫多家 | P0 |
| 岗位卡片 | 标题/地点/JD 预览/官网链接 | P0 |
| 感兴趣清单 | 加入、状态、备注、导出 | P0 |
| 公司池管理 | 已接入 / 全库加入 / 待接入 | P0 |
| 门户一键接入 | 识别飞书/Moka/北森 URL 写入可拉岗池 | P0 |
| Agent 工作流可视化 | 蓝图 + 运行回放漏斗 | P0 |
| AI 点评 | Agnes 打分、匹配点、缺口、行动建议 | P0 |
| 简历匹配 | 上传 PDF/Word，对照 JD 评匹配度并给优化建议 | P0 |
| 导出 | JSON / CSV | P1 |
| PRD 页 | 系统内可读产品文档 | P1 |

### 4.2 Agent 流水线

| 步骤 | 角色 | 实现方式 |
| --- | --- | --- |
| 听懂目标 | 意图理解 | 赛道 / 地点 / 关键词 / 画像 |
| 选择信息源 | 路由规划 | 公司 key → ATS 解析器 |
| 自动取岗 | 数据采集 | Hiring-Radar 本地解析脚本 |
| 判断匹配 | 规则过滤 | 关键词 · 地点 · 时效 |
| AI 点评 | 大模型推理 | Agnes 2.5 Flash API |
| 输出结果 | 交付 | 卡片 · 清单 · 导出 |

说明：**拉岗与规则过滤不依赖大模型**；**点评与匹配解读依赖 Agnes**。二者解耦，无 Key 时前半段仍可用。

## 6. 体验需求

- 支持本机调试与服务器部署，外部用户可通过公网 URL 访问工作台  
- 密钥仅存环境变量 / 服务器侧 `.env`，不进 Git、不暴露到前端  
- 隐藏 Streamlit Deploy 英文控件，保留侧栏展开能力  
- 暖色卡通视觉；桌面 / 平板 / 手机基础适配  

---

## 7. 技术架构

```text
[用户浏览器] → 服务器上的 Davina 秋招工作台 (Streamlit :8501 或反代 80/443)
           ├─ radar_service：封装 Hiring-Radar 拉岗 / 过滤 / 轨迹
           ├─ ai_service：Agnes Chat Completions
           ├─ user_prefs.json：感兴趣 / 自定义公司 / 用户接入门户（当前单机文件）
           └─ parsers/*：飞书 / Moka / 北森 / 专项门户
```

| 层级 | 技术 |
| --- | --- |
| 产品层 | Streamlit、本地 CSS 主题、会话状态 |
| 数据层 | Hiring-Radar、companies.seed、companies.user.seed |
| 智能层 | Agnes `agnes-2.5-flash`，Base `https://apihub.agnes-ai.com/v1` |
| 部署层 | 云服务器 + 进程守护（systemd / Docker）+ 可选 Nginx HTTPS 反代 |

---

## 8. 数据与合规

- 岗位数据来自目标公司公开招聘门户 / ATS 接口，仅供个人求职辅助  
- 不爬取登录墙后隐私数据；遵守目标站点合理使用频率  
- API Key 与用户画像默认存在运行环境（本机或服务器），不写入公开仓库；调用 Agnes 时才会把岗位摘要与画像发往模型接口

## 9. 指标与验收

| 指标 | 验收方式 |
| --- | --- |
| 可拉岗公司 | 全库可枚举；赛道 enabled 可检索 |
| 单次检索 | 返回 total / matched，工作流可回放 |
| AI 点评 | 配置 Key 后单条/批量返回 score 与建议 |
| 感兴趣 | 刷新后仍在；可导出 |
| 门户接入 | 粘贴合法 ATS URL 后出现在本赛道可选公司 |
